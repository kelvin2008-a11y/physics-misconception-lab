# 물리 다시보기

대학 일반물리의 문제와 손글씨 풀이를 근거로 살펴보는 정적 한국어 학습 사이트입니다. 빈 개인 키는 설정된 공용 백엔드를 사용하고, 입력한 개인 키는 브라우저에서 직접 OpenAI Responses API를 호출합니다. **실제 API의 물리 진단 품질은 미검증**입니다. 완료 검증은 모의 API 응답과 Playwright 브라우저 테스트로 수행합니다. 실제 유료 호출은 하지 않았습니다.

## 실행과 검증

Node 22 이상에서 다음 명령을 실행합니다.

```sh
cd outputs/physics-lab
npm install
npx playwright install chromium
node scripts.mjs test
node scripts.mjs build
python3 -m http.server 8080 --directory dist
```

런타임 의존성이나 외부 스크립트는 없습니다. 정적 프런트엔드는 Pages에, 공용 분석 백엔드는 Render에 별도로 배포합니다. ES module 때문에 file:// 열기는 지원하지 않습니다.

## 학습 흐름

1. 이름·학번을 가린 문제 텍스트/이미지와 별도의 풀이 이미지/텍스트를 넣습니다. 교사 참고 기준은 선택입니다.
2. PNG/JPEG/WebP 최대 8장, 장당 10 MiB, 원본 총 24 MiB를 허용합니다. 긴 변 2400px PNG로 변환하며 확대 미리보기로 작은 글씨를 확인할 수 있습니다. PDF는 이미지 변환 후 사용하세요. 읽기 어려운 경우 선명한 부분 이미지를 다시 올리세요.
3. 키를 비워 공용 서버를 사용하거나 개인 API 키와 접근 가능한 모델을 입력하고 분석합니다. 모델 기본값은 이미지 입력과 Structured Outputs를 지원하는 `gpt-6.1-terra`이며 계정별 접근 가능 여부는 다릅니다.
4. 전사·옳은 부분·인용 및 위치 근거·오류 종류·힘의 주체/대상·확신도를 확인합니다. 확신도는 정답 확률이 아닙니다. 불충분한 입력은 판단 보류로 표시합니다.
5. 세 힌트, 전체 참고 풀이, 새 재도전 문제를 이용하세요. 재도전 답안은 새 API 호출로 검토합니다. 401/403/429/서버/네트워크/미완료/거절/잘못된 구조를 구별하며 자동 재시도는 없습니다. 취소는 브라우저 요청을 중단하며 이미 처리된 요청의 요금 취소를 보장하지 않습니다.
6. 교사가 진단 수락/수정 후 보고서를 미리 확인합니다. 수정 내용이 원 AI 진단보다 우선합니다. 보고서는 입력·전사·직접 인용·이미지·키를 제외하고 일부 식별정보를 지웁니다. 자유 서술에 남은 개인정보는 자동으로 완벽히 제거할 수 없으므로 편집 가능한 JSON 미리보기와 확인란을 거쳐 개인 파일로 저장/인쇄합니다. 재도전 결과는 화면에서 별도 확인하며 기본 보고서는 최초 진단에 대한 검토입니다.

## 개인정보와 한계

키는 비밀번호 입력 필드의 메모리에만 존재하며 저장소·URL·로그·보고서에 쓰지 않습니다. 키 지우기와 페이지 이탈은 키를 지우고 요청을 취소합니다. 입력·이미지는 분석 요청 때 OpenAI로 전송되며 제공자의 데이터 정책이 적용됩니다. `store:false`를 사용하며 앱 자체는 서버 저장·분석 추적·자동 저장을 하지 않습니다. 새로고침하면 작업을 잃습니다. AI 지시문과 첨부를 분리하고 첨부를 신뢰하지 않도록 지시하지만 모델의 지시 준수나 진단 정확성을 보장하지 않습니다. 오류를 항상 원문과 대조하세요. 출력은 HTML로 해석하지 않습니다.

## 합성 자료

API 없이 동작하는 **합성 데모**는 실제 업로드 진단이 아닙니다. 별도 라이브러리에는 48문항 × 20사례 = 960사례가 있으며 그중 작용·반작용/평형 집중 사례는 204개입니다. HW2–5는 문항당 10개 오류 계열 × 2개 표현 형식입니다. 기존 `outputs/과제1-5_통합_오답사례_960개.jsonl`의 교육용 내용과 `work/all_payload.json`의 문항 목록을 화이트리스트로 추출했습니다. 성적 통계, 원본 PDF, 이름, 학번, 개별 학생 점수는 번들에 포함하지 않습니다. 선택한 문항의 재계산 정답 기준과 제공 채점기준은 참고 입력에 연결합니다. 오류 발생 비율로 해석하면 안 됩니다.

## 사진에서 확인한 교정 사례 기억하기

진단 뒤 ‘현재 진단으로 기억할 내용 준비’를 누르면 문제 요약과 참고 풀이가 채워집니다. 교사 수정 상태라면 수정한 풀이를 사용합니다. 내용을 직접 고치고 개인정보를 지운 뒤 확인란을 선택해야 저장됩니다. 자동 저장은 없습니다. 원본 사진·전사 전체·API 키는 저장 대상이 아니며 입력한 두 텍스트 필드만 이 브라우저의 저장 공간에 남습니다. 다른 기기로 자동 동기화하지 않습니다.

다음 진단에는 관련 텍스트 사례 최대3개를 참고 기준에 넣습니다. 문제를 사진만 올린 경우 최근3개를 넣습니다. 참고 여부를 끄거나 개별 기억을 삭제할 수 있고, 승인 사례를 JSON으로 내려받을 수 있습니다. 이는 검토된 사례를 참고하는 방식이며 모델 가중치의 재학습이나 fine-tuning 완료를 뜻하지 않습니다. 저장 공간 삭제/시크릿 모드 종료 시 기억이 사라질 수 있습니다. 기존 API 키·사진 자동 저장 금지는 유지됩니다.

## 공용 백엔드 설정 및 부모 배포 안내

Node 22 전용 무의존성 HTTP 서버는 `server/server.mjs`입니다. 저장소 루트의 `render.yaml`은 free 서비스, Node 22, health check, 환경 변수만 정의합니다. 이 작업에서는 push/deploy 또는 실제 API 호출을 하지 않았습니다. 부모 담당자가 배포를 수행해야 합니다.

1. Render Blueprint에 루트 `render.yaml`을 선택합니다. `OPENAI_API_KEY`를 Render 비밀 환경 변수로만 입력합니다. `ALLOWED_ORIGIN`은 프런트엔드의 정확한 origin, 예: `https://kelvin2008-a11y.github.io`로 설정합니다. 경로, 끝 슬래시, 와일드카드는 허용하지 않습니다.
2. 서비스 URL을 받은 후 `assets/config.mjs`의 `BACKEND_URL`에 HTTPS origin을 넣고 정적 사이트를 다시 빌드합니다. 빌드가 CSP connect-src에 설정된 정확한 origin을 추가하므로 반드시 dist를 배포/로컬 제공하세요. `DEFAULT_API_KEY`는 반드시 빈 문자열로 유지합니다. 프런트엔드에는 공개 URL만 넣습니다.
3. 부모가 Render의 `/healthz`와 실제 사이트 연결을 확인합니다. health check는 OpenAI 접근 권한이나 실제 진단 품질을 검증하지 않습니다. 이 작업의 검증은 모두 모의 응답입니다.
4. 로컬에서는 `.env.example`을 `.env`로 복사해 환경 값을 설정하고 `node --env-file=.env server/server.mjs`로 시작합니다. 정적 사이트는 8080 포트에서 제공하고 origin은 `http://localhost:8080`으로 맞춥니다. 실제 키로 분석 버튼을 누르면 비용이 발생하므로 자동 테스트는 모의 upstream만 사용합니다.

공용 API는 `POST /api/diagnose`의 problem/solution/rubric, 역할과 data URL만 가진 images, retry.question만 받습니다. 프롬프트·JSON schema·모델(`gpt-6.1-terra`)·OpenAI URL·store:false는 서버가 고정합니다. 개인 키 경로의 모델 선택은 유지됩니다. 텍스트 필드당 20,000자, 이미지 8장, 이미지 data URL당 14 MiB, 전체 HTTP 본문 36 MiB이며 PNG/JPEG/WebP 시그니처와 base64를 검사합니다. 원본 업로드 제한은 기존대로 유지되지만 PNG 변환 후 용량이 커지면 공용 서버가 413을 반환할 수 있습니다. 이때 이미지 크기를 줄여 주세요.

요청 본문 수신 15초, upstream 응답 전체 45초, upstream 본문 1 MiB 제한입니다. 연결 종료는 upstream 요청을 취소합니다. 인스턴스 전체 동시 요청 2개, 분당 6개, 24시간 100개이며 거절 시 자동 재시도하지 않습니다. 잘못된 요청도 입장 후에는 한도를 소비합니다. IP 헤더를 신뢰하지 않는 전역 메모리 제한이며 재시작 시 초기화됩니다. Origin 검사는 브라우저 접근 통제이지 사용자 인증이 아닙니다. 비브라우저 클라이언트는 origin을 위조할 수 있으므로 부모는 OpenAI 프로젝트 예산/사용량 경고도 설정하고 공용 서비스 사용량을 관리해야 합니다. 무료 호스팅의 절전/콜드 스타트로 첫 연결이 지연될 수 있습니다.

서버는 입력·사진·키·upstream 오류 본문을 파일, 데이터베이스, 로그에 저장하지 않습니다. 처리 중 메모리만 사용하고 결과와 토큰 수만 응답하며 no-store를 지정합니다. API 키는 환경 변수에만 둡니다. 호스팅 제공자 및 OpenAI의 자체 데이터 정책은 별도입니다. 기존 사용자 확인 후 저장하는 브라우저의 교정 사례 기억, 이미지 입력, 960개 합성 사례는 유지됩니다. 계정·DB·fine-tuning은 추가하지 않았습니다.

검증: `npm test`, `npm run build`. 테스트는 로컬 HTTP, 고정 계약, 입력/Origin 차단, 크기/한도/타임아웃, 오류 비밀 제거, 공용/개인 경로 및 기존 브라우저 회귀를 확인합니다.


## 비교과지니 서브페이지

`bgg-gini/`는 기존 녹색 UI, 관심사 칩, 안내, 카드와 94개 저장 목록을 보존합니다. 물리 페이지와 상대 경로로 왕복하며 빌드에 포함됩니다. 기존 공개 `/programs` 서비스는 그대로 사용합니다. 갱신 실패/20시간 이상 지난 목록은 화면에 표시하며 원본 일정 확인을 안내합니다.

`POST /api/bgg-recommend`는 `{interest, programs}`만 받습니다. 후보 5~300개의 고유 SNU 프로그램 URL ID와 제한된 텍스트 필드를 검증하고, 서버 고정 모델/지시문/JSON 스키마로 정확히 5개를 선택합니다. 결과 ID, 중복, 이유, 내림차순 점수를 다시 검증합니다. 후보 및 관심사는 사용자 데이터로만 전송됩니다. 클라이언트에 키 입력이나 키 저장은 없습니다. 기존 `OPENAI_API_KEY`, `ALLOWED_ORIGIN`, `BACKEND_URL` 설정을 함께 사용합니다. `/api/diagnose`와 동일한 프로세스의 전역 분당/일일/동시 요청 한도를 공유합니다. 한도는 프로세스 메모리에 있으므로 재시작 시 초기화되며 여러 인스턴스 사이에는 공유되지 않습니다.

`npm test`는 모의 OpenAI 응답과 브라우저-Node 통합, 오류/한도/텍스트 안전성/서브경로 및 물리 회귀를 검증합니다. 실제 유료 API 호출, 배포, GitHub 푸시는 수행하지 않았으며 실제 추천 품질은 미검증입니다.
